# Security notes

## This is a test-net toolkit

Every private key generated by the example scripts is a throw-away QA-only key. Do NOT:

- Reuse any key generated by these scripts against a mainnet Upside deployment.
- Send real value to any address derived from these keys.
- Assume the QA endpoint (`https://dev.upsidemax.xyz`) is production.

## What you must NOT do

1. **Never** point these skills at a mainnet Upside deployment. All examples call the QA endpoint — do not override to a production URL.
2. **Never** commit user private keys. `.gitignore` covers `*.pem`, `.env*`, `secrets/`, and `wallets/`.
3. **Never** accept a private key over chat with an AI. If an AI asks you for one, refuse and generate a fresh key with `python3 examples/01_register.py`.

## Alpha test invitation code

QA registration requires an alpha test invitation code — request one from the Upside team and provide it via the `UPSIDE_INVITE_CODE` environment variable. Invite codes are per-user and rate-limited.

## Reporting a vulnerability

If you find something that lets any user grant themselves funds, take another user's funds, or bypass the invite gate on production, please file a private security advisory rather than a public issue.
